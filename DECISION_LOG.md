# Architecture & Product Decision Log — «Как Я?»

Этот документ фиксирует все ключевые архитектурные, продуктовые и дизайн-договорённости по приложению «Как Я?».
Каждое решение принято осознанно на основе пользовательских сценариев, требований App Store и удобства мобильного интерфейса.

---

## 1. Идентичность и методология продукта

* **Название приложения:** «Как Я?» (строго с пробелом и знаком вопроса).
  * Используется в title веб-приложения, манифесте PWA (`short_name`), названии закладки на рабочем столе iOS и в карточке App Store.
* **Научный фундамент:** Методика *Mood Meter (Измеритель настроения)* Йельского центра эмоционального интеллекта (проф. Марк Брэккетт, Marc Brackett, Ph.D.).
* **Концепция 4 квадрантов:**
  * 🔴 **Высокая энергия / Неприятно** (Красный — тревога, гнев, напряжение)
  * 🟡 **Высокая энергия / Приятно** (Желтый — радость, вдохновение, бодрость)
  * 🔵 **Низкая энергия / Неприятно** (Синий — грусть, усталость, апатия)
  * 🟢 **Низкая энергия / Приятно** (Зеленый — покой, благодарность, умиротворение)
* **Позиционирование:** Личное пространство для осознания чувств + бережная связь для пар и близких людей без лишних слов.

## 2. Дизайн и UI/UX решения

### 2.1. Нижняя панель навигации (Bottom Tab Bar)
* **Только иконки (без подписей):** Текстовые названия разделов («Главная», «Журнал», «Близкие» и т.д.) убраны, чтобы сохранить лаконичный, премиальный мобильный вид без нагромождения.
* **Иконка первого таба («Сегодня»):** Реализована как симметричный тонкий, но широкий крестик/плюс (`SVG Line width=1.8`, `viewBox="0 0 28 28"`).
* **Состав табов:**
  1. `+` — Сегодня / Быстрый чекин настроения
  2. `book` — Журнал чекинов
  3. `people` — Близкие (чаты и эмоциональный пульс пары)
  4. `pie-chart` — Тренды и аналитика динамики
  5. `settings` — Настройки, язык, методология и профиль
* **Отступ снизу на экранах (Компактный и естественный):**
  * Искусственный отступ `paddingBottom: 130px` **ОТМЕНЕН** по решению пользователя, так как создавал неестественную пустую зону внизу экрана.
  * Установлен стандартный компактный мобильный отступ `paddingBottom: 32-36px` (`HomeScreen`, `JournalScreen`, `FriendsScreen`, `TrendsScreen`, `SettingsScreen`).
  * Безопасная зона для устройств с Home Bar контролируется аппаратно через безопасные отступы панели (`env(safe-area-inset-bottom)`).

### 2.2. Уникальные иконки квадрантов (вместо однотипных сердечек)
В карточках чекинов и чатах перед каждым чувством отображается индивидуальная геометрическая закрашенная фигура:
* 🔴 **Красный:** 10-конечная острая звезда («колючка / шип») — символизирует внутреннее напряжение или взрыв эмоций.
* 🟢 **Зеленый:** Облачное скругленное сердце — гармония, уют и бережное принятие.
* 🟡 **Желтый:** Облачная молния / заряд энергии — подъем сил, вдохновение и радость.
* 🔵 **Синий:** Облачное кольцо с вырезанным отверстием («donut ring») — глубина, уязвимость и пространство для проживания грусти.

### 2.3. Главный экран (Home)
* Крупная центрированная кнопка **«Отметить состояние»** для удобного нажатия одним пальцем на ходу.
* Блок **«Цитата»** (ранее «Мысль дня») вынесен над чекином с поддержкой смены цитаты по тапу.
* В графике карты динамики настроения **убрана нижняя легенда**, чтобы график занимал максимум полезной площади.

## 3. Архитектура пользователей и авторизация

### 3.1. Единая сущность аккаунта (Account Entity & Multi-Provider Linking)
* **Первичный ключ:** Внутренний неизменный `user_id` (UUID v4 в PostgreSQL).
* **Внешние провайдеры:** `google_id`, `telegram_id`, `telegram_username`, `apple_id` — внешние привязки к одному аккаунту, а не первичные ключи.
* **Автоматическое связывание (Account Linking):**
  * Если авторизованный пользователь (с `Bearer` токеном в заголовке `Authorization`) заходит через Apple ID или Telegram, сервер не создает новый аккаунт, а привязывает провайдер к текущему `user_id`.
  * Если пользователь изначально вошел через Google (`user@gmail.com`), а затем авторизуется через Apple ID с тем же email или инвайт-кодом — сервер находит существующий профиль и связывает `apple_id` с существующим `user_id`.
  * Все связи с близкими, переписка и сохраненные чекины остаются на месте.

### 3.2. Авторизация Sign in with Apple (iOS Guideline 4.8)
* **Нативное приложение iOS (App Store / TestFlight):**
  * Реализовано через официальный пакет `expo-apple-authentication`.
  * Вызывает нативную системную шторку iOS с биометрией (Face ID / Touch ID).
  * **Решение проблемы повторного входа iOS:** В нативном iOS SDK параметры `credential.fullName` и `credential.email` приходят **только при первой авторизации**. На сервере реализовано безопасное декодирование `identityToken` (JWT) для извлечения неизменного клейма `sub` (постоянный Apple User ID) и email при перепривязке.
  * SHA256-хэширование всего токена **устранено**, так как оно генерировало случайные ID при каждом входе из-за изменения `iat/exp` в JWT. Теперь используется постоянный `sub`.
* **Веб-версия (Safari / Chrome):**
  * Вместо создания фиктивных одноразовых пользователей открывается модальное окно Apple ID.
  * Пользователь вводит свой Apple ID (email / iCloud), и приложение связывает сессию с реальным профилем по email, инвайт-коду или активному токену.

### 3.3. Авторизация Telegram (Dual-Identity Unification)
* **Разделение числового ID и никнейма в базе:**
  * Добавлена отдельная колонка `telegram_username` с регистронезависимым индексом `LOWER(telegram_username)` в дополнение к `telegram_id` (числовой ID Telegram).
* **Устранение дубликатов между Web, ботом и WebApp:**
  * Ранее вход по `@username` в веб-модалке сохранял текстовый никнейм в `telegram_id`, из-за чего последующий вход через Telegram Bot (`from.id`) или Telegram WebApp не находил пользователя и создавал дубликат профиля с пустыми чекинами.
  * Теперь при любом типе входа поиск выполняется по объединенному условию:
    `telegram_id = $1 OR LOWER(telegram_username) = $2 OR email = $3 OR google_id = $4 OR invite_code = $5`.
  * При совпадении никнейма числовой `telegram_id` автоматически дописывается в существующий профиль, и наоборот.
* **Telegram Mini App (WebApp):**
  * Автоматический бесшовный вход через `window.Telegram.WebApp.initDataUnsafe` с передачей как `id`, так и `username`.
* **Telegram-бот (Deep Link):**
  * Поддерживает сессии `/start auth_<code>`. Бот корректно связывает сессию с аккаунтом по `telegram_id` и `telegram_username`.

### 3.4. Прозрачность активного профиля
* В шапке раздела «Близкие» и в настройках всегда отображается плашка текущего пользователя (аватар, имя, логин, бейдж провайдера `Apple ID` / `Telegram` / `Google`) и кнопка **«Сменить»** для быстрого перехода между профилями в один тап.

### 3.5. Исключение демо-аккаунтов из интерфейса
* Кнопка «⚡ Быстрый вход (Демо-аккаунт)» и всплывающие окна выбора демо-пользователей («Вася» / «Лиана» / «Аня») **полностью убраны из пользовательского интерфейса** (`SettingsScreen`, `FriendsScreen`, `AuthContext`).
* Интерфейс очищен от тестовых элементов для продуктового релиза; поддерживаются реальные методы аутентификации (Apple ID, Telegram, Google).

## 4. Раздел «Близкие» (Парная механика и чаты)

* **Подключение партнера:**
  * По персональному 6-значному инвайт-коду.
  * По умной ссылке для мессенджеров: `https://how-am-i.famehub.ru/?invite=CODE&from=Name#friends`.
  * **Текст приглашения (бережный и емкий):**
    > *«Привет! Я отмечаю своё состояние в приложении «Как Я?». Давай будем на связи, чтобы бережно делиться тем, как мы себя чувствуем: [URL]»*
* **Архитектура чата:**
  * Список чатов (Telegram/WhatsApp style) с аватарами, цветным кольцом настроения партнера и индикатором онлайна.
  * Выделенная комната диалога с непрерывным поллингом сообщений.
  * Однострочное компактное поле ввода сообщения (`height: 38`, `multiline={false}`) с быстрой кнопкой отправки стрелкой вверх.
* **Карточки настроения в чате:**
  * Возможность отправить карточку чекина в чат прямо из диалога (кнопка «Поделиться состоянием»).
  * В чате карточка отображается в фирменном стиле квадранта с кастомными иконками, заметкой и быстрыми реакциями заботы в 1 клик:
    * 🤗 *Обнять*
    * 🤍 *Я рядом*
    * 🌟 *Горжусь*
    * ☕ *Поговорить*
    * 💭 *Спросить «Как ты?»*

* **Управление отправкой чекинов близким (Default Sharing & Manual Toggle):**
  * В «Настройках» (`SettingsScreen`) добавлен переключатель **«Отправлять чекины близким»** (сохраняется в `@how_am_i_default_share_partners_v1`).
  * Поле шеринга перенесено **в самый конец чекина** (`CheckInModal`, после тегов контекста и заметки, прямо над кнопкой «Завершить чекин»).
  * **Поведение при настройке «Нет» (личные чекины по умолчанию):**
    * Чекин открывается со статусом `shareWithPartners = false`.
    * В конце чекина поле переходит в состояние личного чекина: штрихованная рамка, бейдж `Только мне`, иконка замка и четкий призыв: *«👉 Нажмите или потяните тумблер для отправки»*.
    * Если пользователь не дернул тумблер вручную, чекин сохраняется только локально в его личный дневник.
    * Если пользователь дернул тумблер — чекин подсвечивается изумрудным бейджем `Отправится` и пушится близким.

* **Обновление кнопки и модалки «Отметить состояние» в чате (Tactile Chat Check-In):**
  * **Кнопка в строке чата:** Заменена устаревшая базовая кнопка на современную тактильную панель:
    * Иконка `sparkles` в неоновом круге `#4FD1C5` на полупрозрачной подложке.
    * Заголовок **«Отметить состояние»** + подпись с именем собеседника.
    * Правый кластер с 4 цветными микро-точками квадрантов (`#F56565`, `#ECC94B`, `#4299E1`, `#48BB78`) и стрелкой `chevron-up`.
  * **Шторка «Отметить состояние» (`shareZenCard`):**
    * Полностью переработана карточка быстрого чекина: глубокий фон `#141A24`, скругления 22px, изумрудная рамка с мягким свечением.
    * Наглядные интерактивные бейджи 4 квадрантов: Красный, Жёлтый, Синий, Зелёный.
    * Кнопка **«Открыть карту 144 чувств»** выполнена в фирменном неоново-бирюзовом градиенте `#4FD1C5` с темным текстом `#0A0D12` и эффектом глубины.
  * **Карточки недавних чекинов:**
    * Индивидуальный цвет левого бордера и бейджа квадранта.
    * Индикатор отправки стрелкой в цвет квадранта настроения.
  * **Ответ на заботу («Как ты?»):** Кнопка ответа оформлена в едином тактильном стиле с иконкой искорок.

## 5. Инфраструктура и развертывание

* **Боевой сервер (VPS):**
  * IP: `5.129.238.166`, ОС Linux / Docker.
  * Домен: `https://how-am-i.famehub.ru` с автоматическим SSL Let's Encrypt и HTTP/2.
  * Контейнеры:
    * `howami_api` — Node.js Express API + раздача статики React Native Web.
    * `howami_postgres` — PostgreSQL 16 (`howami_user`, база `howami_db`).
    * `nginx_nginx` — Nginx Reverse Proxy.
* **Скрипт деплоя:**
  * Локальный скрипт `scratch/deploy.py` собирает web-бандл (`npx expo export --platform web`), внедряет метатеги PWA, формирует архив и заливает по SFTP/SSH в Docker-контейнер с перезапуском API.
* **Борьба с кешированием в мобильных браузерах:**
  * Заголовки `Cache-Control: no-cache, no-store, must-revalidate` для `index.html`.
  * Хэширование и версионирование бандла (`?v=timestamp`).
  * Скрипт автоматической дерегистрации устаревших Service Worker.

## 6. Правила разработки проекта

1. **Синхронизация с GitHub:** Проект синхронизируется с `https://github.com/zinnatik24/how-am-i` (ветка `main`).
2. **Mobile-First приоритет:** Любые изменения UI проверяются на мобильном экране iPhone (390x844) с учетом системных безопасных зон и панелей Safari.
3. **Сохранение целостности методологии:** Термины и психология методики Yale Mood Meter должны оставаться научно корректными.
